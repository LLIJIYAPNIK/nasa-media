# TZ-web-homepage-fixes-round3.md — третий раунд доработки главной страницы

## Контекст

Первые два раунда (`docs/tz/web-homepage-fixes/`,
`docs/tz/web-homepage-fixes-round2/`) реализованы и слиты в `main`
(`fix/web-homepage-polish`, `fix/web-homepage-polish-round2`). После
очередной живой проверки автор попросил три вещи: увеличить Землю, убрать
оставшееся вращение и сделать небо Nightreign ближе к референсу — конкретный
скриншот из игры (`elden-ring-nightreign-adel-nightlord-door.webp`,
не коммитится в репозиторий — только источник вдохновения для палитры/формы,
как и раньше зафиксировано в `TZ-web-homepage-fixes.md`, п. 7: копировать
ассеты игры нельзя, переносится только настроение).

## 1. Земля маленькая

**Причина (`presentation/web/static/css/earth.css`):** `.earth-mount` —
`width: min(70vw, 1100px)`. Это расхождение с самим ТЗ на дизайн
(`docs/tz/TZ-web.md`, п. "Источник дизайна": "крупная вращающаяся 3D-Земля
справа (**85–90% экрана**...)") — комментарий в начале `earth.css` даже
цитирует "85-90% экрана", но значение в коде этому не соответствует и
никогда не соответствовало ни в одном из двух раундов правок (оба раунда
трогали `earth.js`/сам факт вращения, не этот конкретный размер). Правка —
не новое решение, а приведение кода в соответствие с уже согласованным ТЗ.

**Решение:** `width: min(88vw, 1500px)` (десктоп). Высота остаётся `100vh` —
уже соответствует спеке. Мобильный брейкпоинт (`max-width: 768px`) —
`height` увеличена с `55vh` до `62vh`, чтобы увеличение не потерялось на
маленьких экранах, `opacity` и смещение (`right: -25%`) — без изменений (там
Земля намеренно приглушена, чтобы не спорить с контентом на узком экране).

## 2. Земля всё ещё "вращается" — в CSS-фолбэке

Round 2 (п. 2) убрал постоянное вращение из WebGL-сцены (`earth.js`,
`ROTATION_SPEED`) — сфера теперь статична, наклоняется только за курсором.
Но у CSS-фолбэка (`.earth-fallback`, показывается когда WebGL недоступен —
`prefers-reduced-motion`, ошибка создания рендерера) осталась своя, отдельная
анимация: `animation: earth-drift 240s linear infinite;` двигает
`background-position` по кругу. Это тот же самый баг, что round 2 фиксировал
в WebGL-пути, только не замеченный там — фолбэк не тестировался отдельно.
Раз "Земля статична" — требование к дизайну модели, а не к конкретному
рендер-пути, фолбэк должен вести себя так же.

**Решение:** убрать `animation` из `.earth-fallback` и весь блок
`@keyframes earth-drift` целиком; заодно убрать теперь бесполезный
`@media (prefers-reduced-motion: reduce) { .earth-fallback { animation: none; } }`
— отключать уже нечего. `background-position: 0 50%` остаётся статичным
значением (тот же кадр, что и раньше был начальным кадром анимации).

## 3. Небо Nightreign не похоже на референс

**Текущее (`layout.css`, `body::before`/`body::after`):** один
`conic-gradient` (6 цветовых остановок, `blur(60px)`) + один пульсирующий
`radial-gradient` в центре. Плоско по сравнению с референсом — на скриншоте
чётко читается воронка/фунтенель, сходящаяся к яркому бело-фиолетовому
"глазу" с тонкими волокнами-протуберанцами, расходящимися лучами, и тёплым
(розовато-оранжевым) отсветом ближе к горизонту под воронкой.

**Найденный по пути баг рендеринга (важнее самого редизайна):** первая
версия правки (более контрастный `conic-gradient` + `repeating-conic-
gradient` для волокон, фон по-прежнему на `html, body`) в браузере оказалась
вообще не видна — ни на скриншоте, ни при принудительном `background: red`
на `body::after` для диагностики. Причина: в Chromium фон, заданный на
`body`, используется как фон canvas и рисуется **поверх**
`position: fixed` потомков с отрицательным `z-index`, а не позади них, как
можно ожидать по CSS2.1 painting order для обычных (не canvas) элементов —
подтверждено эмпирически (удаление `background` с `html, body` сразу
проявило вихрь). **Решение:** `html, body` больше не задаёт `background`
вообще — весь фон страницы (глубокий космос + вихрь + тёплый отсвет)
собран как слои `background` внутри самого `body::before`, который остаётся
на `z-index: -1`, но теперь ничто на body/html не может его перекрыть.

**Решение по самому виду (только CSS-градиенты + процедурная SVG-текстура,
без ассетов игры — тот же принцип, что и в первом раунде):**

- `body::before` — четыре слоя одним элементом: виньетка
  (`radial-gradient` с `closest-side`, прозрачная в центре, тёмная к краям
  — даёт эффект воронки/фунтенели с затуханием к краям экрана вместо
  равномерной по всему вьюпорту заливки), `conic-gradient` вихря (больше
  цветовых остановок, резче переходы между фиолетовым/индиго/маджентой),
  тёплый отсвет снизу (`linear-gradient`, `soft-light`), и в самом низу —
  базовый радиальный космический градиент (бывший `html, body`). Один общий
  `filter: blur(42px) saturate(1.25)` на всё.
- `body::after` — яркая почти белая сердцевина воронки (`radial-gradient`)
  плюс процедурная текстура волокон: новый файл
  `presentation/web/static/images/nightreign-sky-swirl.svg` (`feTurbulence`
  + `feColorMatrix`, тонируют шум в фиолетовый) — генератор шума, а не
  растровый ассет игры, тот же принцип, что уже применяется в
  `starfield.js` для звёзд (генерировать, не хардкодить/копировать). Слой
  подключается как обычный `background-image` по `url(...)`, не как
  base64-блок в CSS — читаемый файл, не непрозрачная строка в стилях.
  `mix-blend-mode: screen`, лёгкий `blur(3px)` — волокна остаются тоньше
  самого вихря.
- Анимации (`nightreign-spin`, `nightreign-pulse`) и уважение
  `prefers-reduced-motion` — без изменений, тот же принцип, что и раньше:
  без анимации вихрь остаётся статичным, не исчезает.
- Порядок и `z-index` слоёв (небо ниже `.stars`, `.stars` ниже
  `.earth-mount`, всё ниже `.page-content`) — без изменений по значениям,
  round 2 уже зафиксировал это как правильный; изменилось только то, что
  сам фон страницы больше не участвует в этом стекинге через `html, body`
  (см. баг выше).

## Тестирование

Как и в первых двух раундах — визуальная полировка без бизнес-логики,
автотестов на конкретный вид не заводится (WebGL/CSS-анимации не юнит-
тестируются в проекте, см. `TZ-web.md`, `TZ-web-homepage-fixes.md`).
Проверяется вручную в браузере (desktop + мобильная эмуляция) через
`uv run uvicorn presentation.web.app:app`: Земля физически крупнее и не
крутится ни в WebGL-, ни в fallback-режиме (эмулируется через
`prefers-reduced-motion: reduce` в DevTools), небо визуально ближе к
референсу. Существующий набор (`uv run pytest`, `ruff`, `mypy`) прогоняется,
чтобы не сломать роутинг/остальной бэкенд — эти файлы его не касаются, но
это дешёвая проверка.

## Что осознанно вне рамок

- Точная пиксельная копия референсного изображения — палитра/форма
  воронки, не буквальная репродукция скриншота игры (см. п. 7 первого
  раунда: ассеты игры не копируются).
- Настраиваемые параметры вихря (цвета/скорость/размер как конфигурация) —
  фиксированные значения в CSS, как и в предыдущих раундах.
