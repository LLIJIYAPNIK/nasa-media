# TZ-asteroid-comparison.md — сравнение астероида со знакомым объектом

## Цель

Реализовать пункт 7 текущего фокуса: строка про астероид в дайджесте сейчас
даёт диаметр в метрах ("165–368 м") — число, которое никто не чувствует
интуитивно. Добавляем сравнение с узнаваемым объектом ("размером с футбольное
поле"), чтобы факт был понятен с одного взгляда и им хотелось поделиться.
Самая маленькая фича из всего набора — правится одна доменная функция, без
новых портов, клиентов или таблиц.

## Где именно живёт изменение

Единственная точка входа — `_format_asteroid()` в `domain/digest/digest_text.py`
(строки 51-59). Сейчас она собирает `"{диаметр} м, пролетит на {N} лунных
расстояниях"`. Меняется только формирование строки диаметра: вместо голого
числа — числа + сравнение.

## Решения по неоднозначностям

- **Новая чистая функция `compare_to_familiar_object(diameter_m: float) -> str`
  в `domain/digest/size_comparison.py`**, не инлайн в `_format_asteroid`. Та же
  логика вынесения отдельно тестируемой чистой функции, что уже применена для
  `apod_caption.py`/`digest_text.py` — сравнение объектов не имеет отношения к
  сборке текста дайджеста как таковой.
- **База сравнения — `diameter_max_m`, не среднее и не `diameter_min_m`.**
  NASA даёт диапазон оценки размера с большой неопределённостью (в живом
  тесте — от 165 до 368 м для одного и того же объекта). Берём верхнюю
  оценку — консервативнее и драматичнее для "вау-эффекта", и то же самое
  решение, которое уже негласно закладывалось при показе диапазона целиком.
- **Таблица объектов — фиксированный отсортированный список порогов, не
  формула.** Подбирать "естественный" объект под любое число процедурно
  (например, через отношение объёмов) даёт технически точные, но
  малоузнаваемые сравнения ("0.7 синих кита"). Простой список
  `(порог_м, объект)` по возрастанию, среди которых выбирается **первый**,
  чей порог `>= diameter_m`; если ничего не подошло — самый крупный объект
  списка с оговоркой "крупнее, чем...". Пример списка (не окончательный,
  можно скорректировать по вкусу при реализации):
  ```
  10   → "с городской автобус"
  30   → "с синего кита"
  50   → "с половину футбольного поля"
  110  → "с футбольное поле"
  330  → "с Эйфелеву башню"
  830  → "с Останкинскую башню в три раза"
  ```
- **Формат в подписи — уточнение в скобках, диаметр не убирается.** Итоговая
  строка: `"165–368 м (примерно с футбольное поле)"` — число остаётся для тех,
  кому нужна точность, сравнение добавляется, а не заменяет.
- **Метры, не футы/другие единицы** — проект уже везде на метрической
  системе (диаметр, дистанция в километрах), сравнение не должно вводить
  вторую систему единиц.

## Целевые файлы

```
domain/digest/size_comparison.py — compare_to_familiar_object(diameter_m) -> str,
  чистая функция с фиксированной таблицей порогов.

domain/digest/digest_text.py — _format_asteroid() вызывает
  compare_to_familiar_object(highlight.diameter_max_m) и вставляет результат
  в скобках после диапазона диаметра.
```

## Тестирование

- `tests/domain/test_size_comparison.py` — граничные значения таблицы (ровно
  на пороге, чуть меньше, чуть больше), значение меньше первого порога,
  значение больше последнего порога (ветка "крупнее, чем").
- `tests/domain/test_digest_text.py` — обновить существующий сценарий с
  астероидом: подпись содержит сравнение в скобках.

## Что реализовано

Диаметр астероида в дайджесте сопровождается понятным бытовым сравнением,
подобранным по фиксированной таблице порогов от максимальной оценки размера.

## Что осознанно вне рамок

- Сравнения для массы/скорости астероида — только размер, как и было
  запрошено.
- Локализация таблицы объектов под разные страны/культуры — один
  русскоязычный список объектов, без вариативности.
