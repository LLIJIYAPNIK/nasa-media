# TZ-web-homepage-fixes-round4.md — четвёртый раунд доработки главной страницы

## Контекст

Round 3 (`docs/tz/web-homepage-fixes-round3/`) слит в `main` (#22). После
живой проверки — три новых пункта от автора: Земля крупнее и сдвинута
вправо (только на десктопе), ярче на фоне теперь насыщенного неба, плюс
проход по шрифтам в модальных окнах.

## 1. Земля вдвое крупнее и сдвинута вправо — только на больших экранах

**Причина того, что размер не менялся так просто через CSS:** `.earth-mount`
(контейнер) и реальный размер сферы — разные вещи. Сфера рисуется
`PerspectiveCamera` с вертикальным FOV 45° на дистанции
`camera.position.z = 3.2` от сферы радиусом 1 — увеличение только ширины
CSS-контейнера открыло бы больше пустого места по бокам, но не сделало бы
саму сферу крупнее (вертикальный размер объекта в перспективной проекции
зависит от дистанции камеры и высоты канваса, не от его ширины).

**Решение (`earth.js`):**
- `camera.position.z`: `3.2` → `1.8` на десктопе (даёт видимый диаметр
  сферы примерно вдвое больше — используется в паре с обрезкой контейнером,
  часть сферы уходит за верх/низ кадра, это ожидаемо и совпадает с
  «не видно целый шар»).
- `earth.position.x`: `0` → `0.6` на десктопе — сдвигает сферу в кадре
  вправо, ещё часть уходит за правый край `.earth-mount`
  (`overflow: hidden`) и за край вьюпорта.
- **Только для десктопа.** Оба значения читаются из констант
  (`CAMERA_Z_DESKTOP`/`CAMERA_Z_MOBILE`,
  `EARTH_OFFSET_X_DESKTOP`/`EARTH_OFFSET_X_MOBILE`) и выбираются по
  `window.innerWidth > 768` — тот же брейкпоинт, что уже используется в
  `earth.css`/`layout.css` для мобильной раскладки. Пересчитывается внутри
  уже существующего `resize()` (вызывается `ResizeObserver`), чтобы смена
  ширины окна через брейкпоинт (или поворот устройства) сразу отражалась,
  а не только при перезагрузке страницы. На мобильных значения остаются
  прежними (`3.2`/`0`) — там Земля и так приглушена (`opacity: .55` в
  `earth.css`) и не должна расти вместе с десктопом.
- CSS-фолбэк (`.earth-fallback`, `earth.css`) получил симметричные правки
  для десктопа: `width: 90% → 160%`, `right: -15% → -55%` — тот же эффект
  «крупнее и без видимого целого шара», отдельно на случай
  `prefers-reduced-motion`/недоступного WebGL. Мобильный брейкпоинт получил
  явный откат (`width: 90%`), чтобы не унаследовать десктопное значение.

## 2. Земля слишком тёмная на фоне яркого неба

**Причина:** round 3 сделал небо заметно ярче и насыщеннее (см.
`web-homepage-fixes-round3`), а освещение сцены Земли не трогали —
`AmbientLight(0x334466, 0.5)` + `DirectionalLight(0xffffff, 1.3)` остались
на значениях, подобранных под приглушённый фон round 1/2. Ночная сторона
Земли (город-огни, показывается по текущему времени UTC — см.
`TZ-web-homepage-fixes.md`, п. 2) на фоне тёмного космоса читалась
нормально, но на фоне яркого лилового вихря стала выглядеть как почти
чёрное пятно — слишком сильный контраст.

**Решение (`earth.js`):** подняты интенсивности обоих источников света —
`AmbientLight` `0x334466, 0.5` → `0x5a72a8, 1.2` (светлее и голубее, чтобы
поднять тени по всей сфере, не только освещённую сторону),
`DirectionalLight` `1.3` → `1.9`. Слой городских огней (`nightLights`,
отдельный `ShaderMaterial` с аддитивным блендингом) от сцены не зависит —
поднятие `AmbientLight` не гасит и не размывает сам эффект ночной стороны,
только поднимает базовую яркость материала под ним.

## 3. Шрифты в модальных окнах

**Причина:** `.detail-modal-body p` и `dd` не имели собственного правила
`font` — стояла только унаследованная `font-family` от
`.detail-modal-body`, размер/начертание/line-height оставались браузерным
дефолтом (в отличие от остального текста на странице — например,
`.hero p` уже задаёт `font: 500 16px/1.55 ...` явно). Из-за этого текст
описания APOD и значения `dd` в остальных трёх модалках выглядели плоско
и не по единой шкале с сайтом. Отдельно — `dt`/`dd` в `dl` не были выровнены
по базовой линии (`grid` без `align-items`), из-за разницы кегля
(`dt` 11px моно vs `dd` 16px по умолчанию) лейбл визуально «плавал».

**Решение (`modal.css`):**
- `.detail-modal-body p` — новое правило: `font: 400 15px/1.65
  var(--font-body); color: var(--color-text-dim);` + отступ `14px` между
  абзацами (у последнего убирается). Даёт тексту APOD-описания и подписи
  копирайта комфортный интервал строк вместо браузерного дефолта.
- `.detail-modal-body dd` — было без собственного `font`, стало `font: 500
  15px/1.5 var(--font-body); color: var(--color-text);` — чуть плотнее
  обычного текста (500 вместо 400), чтобы явно читаться как «значение»
  рядом с моно-лейблом `dt`, не сливаясь с обычным телом текста.
- `.detail-modal-body dl` — добавлен `align-items: baseline;` — `dt` и
  `dd` в одной строке грида теперь выравниваются по общей базовой линии
  независимо от разницы в кегле.
- `.detail-modal-body h2` — добавлен `line-height: 1.3` (было не задано,
  бралось браузерное значение ~1.2) — на двухстрочных заголовках (длинные
  названия событий Земли) строки были слишком плотно прижаты друг к другу.

## Тестирование

Визуальная полировка без бизнес-логики — проверено вручную через
`uv run uvicorn presentation.web.app:app` и headless Chromium (desktop
1440×900, мобильная эмуляция 390×844, `prefers-reduced-motion: reduce` для
CSS-фолбэка Земли). Модалки проверены точечной заменой `innerHTML`
представительным контентом в обход реального API-запроса (в деве нет
закешированных данных на сегодня — отдельная, не относящаяся к этой задаче
проблема сидинга БД, не исправлялась в рамках этого раунда). Ротация Земли
перепроверена тем же способом, что и в round 3 (два скриншота с разницей
4 секунды, диф по области сферы) — по-прежнему статична.

## Что осознанно вне рамок

- 500-я ошибка `/api/homepage/details/{kind}` в текущем дев-окружении
  (нет закешированных данных на сегодняшнюю дату в БД) — не связана с
  фронтенд-задачей этого раунда, не исправлялась.
- Точные коэффициенты 2x/яркости — подобраны визуально по скриншотам, не
  вычислены аналитически до пиксельной точности.
