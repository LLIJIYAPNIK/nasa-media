# TZ-web-homepage-fixes-round2.md — второй раунд доработки главной страницы

## Контекст

Первый раунд правок (`docs/tz/web-homepage-fixes/TZ-web-homepage-fixes.md`)
реализован в ветке **`fix/web-homepage-polish`** (поверх
`feature/web-homepage`) — коммиты `cd98910`…`750bc82`. Этот раунд —
продолжение той же ветки, не новая с нуля: ниже разобран актуальный код
именно из `fix/web-homepage-polish`, не из исходной `feature/web-homepage`.
Живая проверка в браузере после первого раунда нашла 5 новых пунктов.

## 1. Небо Nightreign не видно — было пасхалкой, должно быть всегда видимым фоном

**Текущее поведение (`nightreign-easter-egg.js` +
`sky-nightreign.css`):** эффект неба включён условно — 7 быстрых кликов по
`.nav-logo` за 3 секунды переключают класс `body.sky--nightreign`. Автор
site не нашёл этот триггер (сам придумал его как "неочевидную пасхалку" — не
самая удачная идея: то, о чём явно просили как о видимой части дизайна,
не должно быть спрятано за секретным жестом). **Решение, подтверждённое
автором:** небо становится **постоянным фоном страницы**, не пасхалкой.

- Убрать `presentation/web/static/js/nightreign-easter-egg.js` целиком —
  файл и его подключение в `base.html`.
- `sky-nightreign.css`: убрать зависимость от класса `body.sky--nightreign`
  — правила `background`/`::before`/`::after` переносятся на сам `body`
  (или объединяются с существующим фоновым градиентом в `layout.css`, чтобы
  не было двух разных мест, отвечающих за фон `body` — предпочтительно
  объединить в `layout.css` и удалить `sky-nightreign.css` как отдельный
  файл, раз он больше не переключаемое состояние, а часть базового фона).
- Порядок слоёв: вихревое небо (самый нижний, `z-index` ниже `.stars`) →
  звёздное поле (`canvas.stars`, как было) → Земля (`.earth-mount`) →
  контент. Небо не должно перекрывать звёзды — они остаются поверх него
  (лёгкая прозрачность звёзд по умолчанию это уже обеспечивает).
- Анимации неба (`nightreign-spin`, `nightreign-pulse`) — как были, включая
  уважение `prefers-reduced-motion` (отключаются, эффект остаётся
  статичным вихрем без анимации).
- Ничего не остаётся "по умолчанию выключенным" — это теперь и есть
  дефолтный фон сайта.

## 2. Земля не должна постоянно вращаться — только реагировать на курсор

**Текущее поведение (`earth.js`):** `animate()` каждый кадр делает
`earth.rotation.y += ROTATION_SPEED` — постоянное вращение никогда не
останавливается, поверх него лишь дополнительно накладывается наклон за
курсором (`tiltX`/`tiltY` на `rotation.x`/`rotation.z`). По уточнению
автора: в дизайне модель **статична** и реагирует только на движение
курсора — постоянного вращения быть не должно вообще.

- Убрать `earth.rotation.y += ROTATION_SPEED` и
  `clouds.rotation.y += ROTATION_SPEED * 0.4` из `animate()` — `ROTATION_SPEED`
  и сама константа больше не нужны.
- Начальная ориентация (`earth.rotation.y = atan2(...) + Math.PI` —
  полуночная долгота к камере, см. п. 2 первого раунда) остаётся: она
  задаёт статичный поворот, не начальную точку вращения.
- Реакция на курсор (`pointermove`, `pointer: fine`, лерп к целевому наклону)
  — остаётся без изменений, это единственное движение модели теперь.
- **Тач-устройства (нет `pointer: fine`) — без движения вообще**, не
  "автономный дрейф вместо курсора", как было предложено в первом раунде по
  аналогии с a-kulebyakin.ru. Разница принципиальная: там дрейф имитирует
  *отсутствие рук на мыши* для того же эффекта, что и spotlight — а здесь
  модель в дизайне попросту статична, автономная анимация добавила бы
  движение, которого в дизайне нет. Убрать любые заготовки под touch-дрейф,
  если они появились в первом раунде (по коду выше их не было — фиксирую
  явно, чтобы не добавить в этом раунде по инерции из соседнего проекта).
- Облака (`clouds`) — тоже статичны (тот же `rotation.y`, без независимого
  вращения) — раньше их лёгкое отдельное вращение маскировало общую
  статичность сцены; раз сцена теперь полностью статична, паровозиком идёт
  и это.

## 3. Шрифт внутри карточек статистики визуально не читается как изменённый

**Текущее (`glass.css`):** `.stats-row-value { font: 700 15px
var(--font-heading); }` — технически уже `Unbounded` (шрифт применился,
`@font-face` в порядке: строка `format("woff2-variations")` в `fonts.css` —
рабочий, не устаревший синтаксис, дополнительно проверено). Проблема не в
загрузке шрифта, а в том, что `Unbounded` — дисплейный геометричный шрифт,
его характер хорошо считывается в крупном заголовке (`h1`, 46px) и
почти неотличим от обычного жирного гротеска на 15px в одну строку —
поэтому "внутри карточек шрифт как будто не поменялся", хотя формально
поменялся.

**Решение:** `.stats-row-value` переводится на `--font-mono` (`JetBrains
Mono`), не на `--font-heading`. Так вся строка карточки (и лейбл, и
значение) читается одним "телеметрическим" стилем — моноширинный шрифт
отличим от системного фолбэка даже на мелком кегле, в отличие от
дисплейного гротеска. Заодно точнее ложится в задуманный с самого начала
"дэшборд-подобный" характер интерфейса
(`docs/design/PROMPT-claude-design-homepage.md`). `h1`/`.nav-logo`/
`.detail-modal-body h2` остаются на `--font-heading` (Unbounded) — это
крупные акцентные места, где дисплейный шрифт как раз должен быть виден.

Дополнительно (гигиена, не обязательный фикс): в `fonts.css` заменить
устаревшую форму `format("woff2-variations")` на текущий эквивалент
`format("woff2") tech(variations)` — MDN документирует их как
равнозначные, но новая форма — актуальный синтаксис CSS Fonts Module
Level 4, старая помечена как "older non-normalized" запись, оставленная
только для обратной совместимости.

## 4. Модальные окна (кроме APOD) всё ещё маленькие

**Текущее (`modal.css`):** `.detail-modal { width: min(70vw, 900px);
max-height: 78vh; }` — ширина уже одинаковая для всех 4 модалок. Разница в
восприятии — из-за высоты: APOD-модалка содержит `<img>` + абзац описания и
естественно заполняет объём, а модалки астероида/погоды/события Земли —
только `<h2>` + короткий `<dl>` на 2-3 строки, поэтому при той же ширине
получается плоский, визуально "маленький" прямоугольник.

**Решение:** задать модалке ощутимую минимальную высоту вне зависимости от
объёма контента:
- `.detail-modal` — добавить `min-height: min(50vh, 440px)`.
- `.detail-modal-body` — `display: flex; flex-direction: column;
  justify-content: center;` — короткий `<dl>` центрируется по высоте
  внутри увеличенной модалки, а не прилипает к верху, оставляя пустоту
  снизу видимой пустотой (а не просто "модалка стала выше, а контент всё
  ещё в углу").
- Для APOD-модалки (там `<img>` + длинный текст могут превысить
  `min-height`) — `justify-content: center` не мешает обычному потоку,
  элемент просто не центрируется, если контента больше, чем свободного
  места (`justify-content: center` на flex-контейнере с overflow ведёт себя
  как `flex-start`, когда контента больше контейнера — стандартное
  поведение, ничего дополнительно настраивать не нужно).

## 5. Полоса прокрутки должна быть стилизована под страницу

Сейчас скроллбар — системный дефолт (обычно светлый/серый), выбивается на
тёмном стеклянном фоне. Нужна тонкая тёмная полоса в тон интерфейсу — в
двух местах: сама страница (если контент выше `100vh` — например, на
мобильных с более высоким `.hero`) и `.detail-modal` (там `overflow-y:
auto` уже есть для длинных описаний APOD).

Новый блок стилей — в `presentation/web/static/css/layout.css` (общий,
применяется глобально) и там же/в `modal.css` — прицельно для
`.detail-modal`:

```css
html {
  scrollbar-width: thin;
  scrollbar-color: var(--color-accent-soft) rgba(255, 255, 255, .06);
}

::-webkit-scrollbar {
  width: 10px;
}

::-webkit-scrollbar-track {
  background: rgba(255, 255, 255, .04);
}

::-webkit-scrollbar-thumb {
  background: var(--color-accent-soft);
  border-radius: 999px;
  border: 2px solid transparent;
  background-clip: padding-box;
}
```

`scrollbar-width`/`scrollbar-color` — стандартное свойство (Firefox и
современный Chrome/Edge оба поддерживают), `::-webkit-scrollbar-*` — для
браузеров на WebKit/Blink, не понимающих первое свойство в старых версиях;
оба блока не конфликтуют, можно задавать оба сразу. Значения (`10px`,
`rgba(255,255,255,.04)`) — по аналогии с уже существующими в проекте
полупрозрачными тонами (`--color-glass-*`), не новая палитра.

## Тестирование

Как и в первом раунде — это визуальная полировка без бизнес-логики,
проверяется вручную в браузере (десктоп + мобильная эмуляция), автотестов
не заводится. Расширить `tests/presentation/test_homepage_router.py` только
одной проверкой: `GET /` больше не ссылается на
`nightreign-easter-egg.js` (простой grep по HTML-ответу) — чтобы удаление
файла не осталось файлом-сиротой, забытым в шаблоне.

## Что осознанно вне рамок

- Настраиваемая интенсивность/скорость вихря неба — фиксированные значения
  из первого раунда, не выносится в конфигурацию.
- Полноценная адаптация скроллбара под конкретные шрифты страниц — общий
  стиль на весь сайт, отдельного варианта под `.detail-modal` с другим
  цветом не заводится (тот же `--color-accent-soft`).
