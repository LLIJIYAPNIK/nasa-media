# TZ-birthday-cosmic-facts.md — фаза Луны и возраст в оборотах планет

## Цель

Реализовать пункт 8 текущего фокуса: добавить к уже существующему сценарию
"мой космический день рождения" (`docs/tz/TZ-birthday.md`) два факта, не
требующих обращения ни к одному NASA API — чистая астрономическая математика
от даты рождения. Усиливает уже сильную фичу ещё одной причиной
переслать сообщение другу.

## Что уже есть и что меняется

Сейчас `cosmic_birthday`/`finish_birthday` в `presentation/telegram/routers/
apod_router.py` после сохранения даты рождения вызывают `deliver_to(...)` —
пересылают APOD-картинку дня рождения (через уже существующий
`DeliverMediaForDate`) и на этом сценарий заканчивается. Ежегодное
поздравление (`SendBirthdayGreetings`, `application/users/
send_birthday_greetings.py`) шлёт статичный `GREETING_TEXT` через
`GreetingSender.send_text` — отдельным сообщением, в обход admin-чата (эти
данные не кешируются, потому что у каждого пользователя свои).

Факты про Луну и планеты — того же типа, что и `GREETING_TEXT`: персональные,
не кешируемые, отправляются напрямую пользователю. Добавляется одно
дополнительное текстовое сообщение в обоих местах, где сейчас показывается
APOD дня рождения: `cosmic_birthday` (если дата уже сохранена),
`finish_birthday` (после первого ввода), и в `SendBirthdayGreetings.execute()`
(ежегодно).

## Решения по неоднозначностям

- **Оба факта — чистые функции в `domain/users/cosmic_facts.py`, без I/O.**
  Как и `is_birthday_today` в `domain/users/birthday.py` — вычисления от даты,
  никакой сети.
- **Фаза Луны — синодический месяц от известной точки отсчёта.**
  Синодический период Луны — 29.530588 суток. Точка отсчёта — ближайшее
  задокументированное новолуние, например `2000-01-06 18:14 UTC` (общепринятая
  опорная дата в астрономических расчётах). `moon_phase_fraction(day: date) ->
  float` — сколько сотых синодического месяца прошло с опорной даты по модулю
  периода (0.0 = новолуние, 0.5 = полнолуние). `moon_phase_name(fraction: float)
  -> str` — восемь именованных фаз (новолуние / растущий серп / первая четверть /
  растущая луна / полнолуние / убывающая луна / последняя четверть / убывающий
  серп) по диапазонам `fraction`. Разделены на две функции: одна считает
  число, другая классифицирует — так граничные случаи именования тестируются
  отдельно от самого календарного расчёта.
- **Точность фазы Луны — ориентировочная, не астрономическая.** Формула не
  учитывает эллиптичность орбиты и другие поправки (та же оговорка, что и у
  любого упрощённого расчёта фазы Луны без эфемерид) — для развлекательного
  факта в Telegram-боте точность в пределах суток избыточна. Явно не
  претендуем на точность профессиональных альманахов.
- **Возраст в оборотах планет — только Меркурий, Венера, Марс.** Не все восемь
  планет: Юпитер/Сатурн/Уран/Нептун дали бы "0 лет" почти для всех
  пользователей (орбитальный период Юпитера — 12 земных лет, значит
  большинству ещё не исполнился даже один "юпитерианский год") — неинтересный
  факт для большинства аудитории. Три планеты с периодом короче или сравнимым
  с человеческой жизнью дают содержательные числа для любого возраста.
  Периоды (в земных сутках, константы в коде, не конфигурируются):
  Меркурий — 87.97, Венера — 224.7, Марс — 686.98.
- **Расчёт — `(сегодня - день_рождения).days / период_планеты`, округление
  вниз до целого.** "Тебе исполнилось N меркурианских лет" — целое число
  прожитых полных оборотов, не дробное.
- **Функция `planetary_ages(birthday, today) -> Sequence[PlanetaryAge]`**
  (`PlanetaryAge(planet_name: str, age_years: int)` — новый dataclass в
  `domain/users/value_objects.py`), возвращает три записи в фиксированном
  порядке Меркурий → Венера → Марс.
- **Сборка финального текста — `build_cosmic_facts_text(birthday, today) ->
  str`, тоже в `domain/users/cosmic_facts.py`.** Комбинирует фазу Луны и три
  планетных возраста в одно сообщение, по аналогии с `build_digest_text`/
  `build_apod_caption` — сборка текста в domain, вызов — в application/
  presentation.
- **Отправка — новым текстовым сообщением, не дописывается в подпись APOD.**
  Подпись APOD дня рождения уже собирается в `ApodProvider.fetch()` и не
  завязана на дату рождения конкретно (это обычная подпись APOD за дату) —
  вплетать в неё факты означало бы протащить `User`/специфику дня рождения в
  `ApodProvider`, который ничего не должен знать про то, что дата — чей-то
  день рождения. Отдельное сообщение проще и не трогает существующий,
  протестированный код APOD.
- **В ежегодном поздравлении (`SendBirthdayGreetings`) факты идут отдельным
  сообщением после `GREETING_TEXT`**, не заменяют его — та же логика, что и в
  разовом сценарии.

## Целевые файлы

```
domain/users/value_objects.py — PlanetaryAge(planet_name, age_years).

domain/users/cosmic_facts.py — moon_phase_fraction(day), moon_phase_name(fraction),
  planetary_ages(birthday, today), build_cosmic_facts_text(birthday, today).

presentation/telegram/routers/apod_router.py — cosmic_birthday и finish_birthday
  дополнительно шлют message.answer(build_cosmic_facts_text(...)) после
  deliver_to(...).

application/users/send_birthday_greetings.py — SendBirthdayGreetings.execute()
  дополнительно шлёт build_cosmic_facts_text(...) через greeting_sender.send_text
  после GREETING_TEXT.
```

## Тестирование

- `tests/domain/test_cosmic_facts.py`:
  - `moon_phase_fraction` в опорную дату возвращает ~0.0 (само определение
    точки отсчёта делает этот тест самопроверяющимся, без внешних
    астрономических таблиц); ровно через половину синодического месяца от
    опорной даты — ~0.5.
  - `moon_phase_name` — граничные значения между соседними фазами.
  - `planetary_ages` — простые круглые числа дней (например, ровно 2×87.97
    дня → 2 меркурианских года) на всех трёх планетах.
  - `build_cosmic_facts_text` — итоговая строка содержит все три планеты и
    название фазы Луны.
- `tests/presentation/test_apod_birthday.py` — расширить существующие
  `test_cosmic_birthday_delivers_immediately_when_already_set` и
  `test_finish_birthday_saves_and_delivers_when_within_apod_bounds`
  проверкой, что `message.answer` вызывается второй раз с текстом фактов (не
  ломая существующие ассерты на `deliver_media.execute`).
- `tests/application/test_send_birthday_greetings.py` — расширить проверкой
  второго вызова `greeting_sender.send_text` с фактами.

## Что реализовано

Два дополнительных факта (фаза Луны, возраст в меркурианских/венерианских/
марсианских годах) в обоих сценариях показа дня рождения — разовом и
ежегодном, без единого обращения к внешнему API.

## Что осознанно вне рамок

- Другие небесные тела (астероиды, кометы с известным периодом обращения) —
  не запрошено, три планеты покрывают сценарий.
- Точный астрономический расчёт фазы Луны с поправками на эллиптичность
  орбиты — избыточная точность для развлекательного факта (см. «Решения»).
- Карточка-картинка для этих фактов — отдельная фича, `TZ-share-cards.md`,
  реализуется позже и подключается к уже готовому тексту отсюда.
