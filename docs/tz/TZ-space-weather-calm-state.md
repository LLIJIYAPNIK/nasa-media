# TZ-space-weather-calm-state.md — «Спокойствие — это нормально» в модалке космической погоды

## Цель

После `TZ-web-space-weather-detail.md` модалка «Космическая погода» научилась
показывать список всех DONKI-уведомлений за день, но случай «DONKI не прислал
вообще ничего» (`available=False`) по-прежнему рендерится через общий
`renderUnavailable` — голый заголовок + одна сухая строка «Космос сегодня
спокоен.», без какого-либо объяснения. По отзыву автора (на живом
скриншоте) это выглядит скучно. Тот же запрос на «энтузиазм вместо таблицы
характеристик» уже решался для модалки астероида (`TZ-asteroid-modal-details.md`)
— здесь тот же принцип применяется к пустому дню космической погоды: явно
сказать, что спокойствие — обычное состояние, а не признак того, что
что-то не работает, и что заметные события (вспышки, бури) случаются не
каждый день.

Ограничено веб-модалкой карточки «Космическая погода» (`presentation/web`),
только веткой `available=False` (DONKI не прислал ни одного уведомления).
Ветка `available=True` со списком событий (включая случай «есть события, но
не приоритетные» → итог «Спокойно») уже не выглядит пустой благодаря списку
над итоговой строкой — не трогается.

## Решения по неоднозначностям

- **Никаких изменений в backend-контракте.** `available`/`message` из
  `_space_weather_detail` (`application/web/homepage_detail_query.py`) не
  меняются — сообщение по-прежнему короткое и приходит с бэкенда, как и у
  остальных 3 карточек в `available=False` состоянии (единообразие полей).
  Пояснительный текст про «нормальность» спокойствия — статичный, живёт в
  `modal.js`, а не в API: это не факт о конкретном дне, а общее объяснение
  UI, ему не место в доменном/application-слое.
- **Без выдуманных цифр.** Не пишем «события бывают раз в N дней» или
  подобную конкретную статистику — таких данных нет ни в NASA DONKI
  ответе, ни где-либо в проекте (см. правило "не выдумывай факты" в
  CLAUDE.md). Формулировка остаётся качественной: активность Солнца
  цикличная (11-летний цикл), заметные вспышки/бури — не ежедневное
  явление, спокойные дни — обычное дело. Это общеизвестный факт о
  солнечной активности, не придуманный для проекта.
- **Только карточка «Космическая погода» получает свой рендер для
  `available=False`.** Остальные 3 карточки (`apod`/`asteroid`/`earth-event`)
  используют общий `renderUnavailable` без изменений — у их пустых
  состояний нет того же «это нормально, просто редко» подтекста (пустой
  день без APOD — это баг/задержка NASA, а не нормальное состояние; пустой
  день без выдающегося астероида/события Земли — уже обсуждалось и не
  трогается, см. `TZ-web-space-weather-detail.md`, «Что осознанно вне
  рамок»). Поэтому развилка по `kind` вносится в `renderDetail()` —
  `space-weather` теперь всегда идёт через `renderSpaceWeather`,
  которая сама решает, что показать для `available` true/false, а не
  перехватывается общей веткой `!detail.available` раньше остальных.
- **Иконка `🌤️` — та же, что уже используется в Telegram-дайджесте**
  (`_format_space_weather` в `domain/digest/digest_text.py`: `"🌤 Космос
  сегодня спокоен."`) — единообразие тона между двумя поверхностями, не
  новая метафора с нуля.
- **Оформление — центрированный блок (иконка + заголовок-статус + пояснение),
  не список/таблица** — сознательно контрастирует с плотным `<dl>` у
  других карточек, чтобы «пустое» состояние не выглядело как недоделанная
  версия того же паттерна, а как самостоятельный, осмысленно спроектированный
  экран.

## Целевые файлы

```
presentation/web/static/js/modal.js — renderDetail(): space-weather больше не
  перехватывается общим `!detail.available` до диспетчеризации по kind;
  renderSpaceWeather(): ветка available=false рендерит новый calm-state блок
  вместо делегирования в renderUnavailable.

presentation/web/static/css/modal.css — .calm-state/.calm-state-icon/
  .calm-state-headline/.calm-state-note.
```

## Тестирование

Backend-контракт не меняется — новых Python-тестов не требуется (уже
покрыто `TZ-web-space-weather-detail.md`). JS в проекте не покрыт
юнит-тестами (нет JS test runner'а, как и у остальных модалок) — проверка
вручную: скриншот модалки на дне без единого DONKI-уведомления (сравнить с
"было"/"стало"), плюс убедиться, что ветка со списком событий
(`available=True`) не сломалась.

## Что осознанно вне рамок

- **Ветка «есть события, но не приоритетные» (`available=True`,
  `space_weather_summary_label == "Спокойно"`)** не получает того же
  calm-state оформления — она уже не пустая (список выше), это другая
  задача другого масштаба, не тот скриншот, что вызвал запрос.
- **Счётчик «дней с последнего заметного события»** — потребовал бы новый
  источник данных (историю DONKI за прошлые дни) и отдельного бэкенд-поля;
  не запрашивался, не делается в этом заходе.
